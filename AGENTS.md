# Documentation style

These rules apply to every page in docs/. Follow them when you edit a page. They are a short subset of the Google developer documentation style guide, plus two project rules.

## Project rules

- Do not use contractions.
- Do not use colons in prose. Write a separate sentence.

These two rules override the Google guide.

## Voice

- Write to the reader as "you".
- Use active voice and present tense.
- Use short sentences. One idea per sentence.
- Do not use "we", "our", or "us".

## Words

- Use American spelling.
- Use "for example" instead of "e.g." and "that is" instead of "i.e.".
- Use "cannot" instead of "can not".
- Use "webhook", one word.
- Use "email", "internet", and "web" in lowercase.
- Use "URL" and "API" in uppercase.
- Use "setup" as a noun and "set up" as a verb.
- Use "login" as a noun and "log in" as a verb.
- Do not use "simply", "just", "easy", "seamless", "powerful", or "robust".
- Do not use "please".
- Do not use exclamation points.

## Punctuation

- Do not use semicolons or em-dashes.
- Use the serial comma.
- Use code font for code, commands, flags, file paths, and field names.

## Structure

- Use sentence case for headings.
- Keep the existing headings and their order.
- Use a numbered list for steps and a bulleted list for options.
- Put one instruction in each step.
- Do not add a page, section, or example unless the product diff requires it.

## Scope

- Change only what the product diff makes wrong.
- Keep the existing wording where it is still correct.
- Do not change front matter unless a `depends_on` path is wrong.
